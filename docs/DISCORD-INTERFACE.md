# King of the Garbage Hill — Discord Interface (bot commands & in-game UI)

> Code-verified against the working tree of 2026-08-05 (v5.2.17). Companion docs: [ARCHITECTURE.md](ARCHITECTURE.md) (§1 topology — the bot shares the process and `GamesList` with the web server), [WEB-BACKEND.md](WEB-BACKEND.md) (the other frontend; web actions reuse the handlers described here), [GAME-DESIGN.md](GAME-DESIGN.md) (what the actions mean). Russian labels and custom-ids below are load-bearing strings — never paraphrase them.

## 1. Interaction model

- **Text commands** via Discord.Net's command service with automatic module discovery (`CommandHandling.cs:47-50`). Prefix gate (`HandleCommandAsync`, `CommandHandling.cs:155-186`): literal `*` (with or without space), bot mention, the account's personal `MyPrefix`, **or any message at all in DMs** (`GuildName == "DM"`, `CommandHandling.cs:180`). Presence advertises `*st - Запустить игру` (`Program.cs:70`).
- **Buttons + select menus** are the only component interactions: `ButtonExecuted` and `SelectMenuExecuted` are wired in the dispatcher's `InitializeAsync` (`DiscordEventDispatcher.cs:37-74`), both `DeferAsync()` then fan out to all four handlers — GameReaction, StoreReactions, TutorialReactions, LoreReactions — each self-selects by message/custom-id (`DiscordEventDispatcher.cs:76-92`).
- **Dead subsystems** (do not build on them): slash commands and context-menu commands are fully implemented but never registered nor subscribed — `Client_HandleSlashCommandAsync` (`CommandHandling.cs:193`) through the four registration helpers (up to `CommandHandling.cs:458`) have no callers; reaction handlers are commented out (`DiscordEventDispatcher.cs:192-214`); there are no modals. The live model is prefix commands + components only.
- **Command-message mirroring**: editing your command re-executes it and edits the bot's reply (`CommandHandling.cs:73-145`); deleting your command deletes the bot's reply (`CommandHandling.cs:52-70`, dispatched at `DiscordEventDispatcher.cs:160-165`). Failed commands reply `Error! {reason}` except silent "Unknown command" (`CommandResults`, `CommandHandling.cs:460-482`).
- No typing indicators (`UserIsTyping` is empty, `DiscordEventDispatcher.cs:94-96`).

## 3. Game start & lobby lifecycle (`*st`)

`General.StartGame` (`General.cs:207-479`) is the whole flow:

1. Rejects the bot itself, unregistered bots, and mentioned players who are already `IsPlaying` (`General.cs:220-237`).
2. Mentioned humans get freed from any bot-seat via `SubstituteUserWithBot`; unspecified slots stay bots (`General.cs:241`); new sequential gameId (`General.cs:244`).
3. Character roll per mode: normal `HandleCharacterRoll`, aram `HandleAramRoll` + `MoveListPage` 5 + bots auto-confirmed (`General.cs:249-264`); shuffle + score-sort (`General.cs:268-269`).
4. **Draft pick applies to Discord games too** when `EnableDraftPick` is on and mode is normal (`General.cs:270-274` — same const as web, `WebGameService.cs:28`): ordinarily natural roll + 2 alternatives per human and `MoveListPage` 6; bots auto-confirm. A naturally rolled unknown_bug is instead silently locked/confirmed and receives no selectable options (`General.cs` draft setup).
5. Team modes split mentions into 2/3-player teams (`General.cs:288-367`); Суппорт + Sirinoks have a 22 % same-team bias (`General.cs:369-404`); teammates auto-predict each other except that no teammate receives unknown_bug's identity (`General.cs` team prediction setup).
6. `GameClass` created with `IsCheckIfReady = false`; ARAM gets `TurnLengthInSecond` 600 (`General.cs:421-427`).
7. Every human gets the **two DM messages** via `WaitMess` (§4) (`General.cs:449`); Nanobot added, teams added, timer started, game listed (`General.cs:454-462`).
8. Round 0 init for plain-normal games only (draft/aram defer it) (`General.cs:466-470`), first `UpdateMessage` per player (`General.cs:472`), a **web link DM** `https://kotgh.ozvmusic.com/game/{gameId}` that auto-deletes next round (`General.cs:474-476`), then `IsCheckIfReady = true` hands control to the 100 ms loop (§6) (`General.cs:478`).

ARAM/draft phase resolution happens inside the loop: ARAM waits for all 6 `IsAramRollConfirmed` then re-sends character sheets and flips to page 1 (`CheckIfReady` ARAM branch); draft defensively auto-confirms any private natural roll/removes its options, waits for all `IsDraftPickConfirmed`, then runs the deferred init (fresh Nanobots/Exploit lists, round 0, timer restart) (`CheckIfReady` draft branch).

Naruto is a natural/draft option only in free-for-all games with two strict bot seats available for clones (a bot original therefore requires a third bot). Round-0 initialization converts those two seats and pre-fills each Naruto's predictions for the other two; ARAM never offers his passive set (`StartGameLogic.cs` `CanNaturallyRollNaruto`, `RollDraftOptions`; `General.cs` draft setup; `Naruto.cs` `InitializeTeam`; `CharactersPull.cs` `GetAramPassives`). For regular users unknown_bug is natural-roll-only: it never enters selectable draft options, store/public catalogs or ordinary force-next mutations, and a private natural result under draft is silently locked rather than exposed. Persistent `PlayerType == 2` accounts alone may select it through the numeric `*st <int>` overload (`AdminPanel.cs:172`) or the web “Тестовая игра” picker.

Every strict bot assignment shares one fail-closed character gate: only Tier 3+ or exact Кира may be assigned. Tier 2, Tier 1, Tier 0/PRO, Tier −1 and every other secret/transform-only character are therefore absent from normal and Ranked bot rosters regardless of Legacy/V2/V3/Legacy+ behavior; deliberate human/admin test selections and the simulation's explicit forced roster are separate surfaces. Ordinary Discord games inherit Legacy+ (level 4) from `GameClass`; Ranked web creation remains explicitly V3 (`StartGameLogic.CanNaturallyAssignToBot`; curated-lobby defenses in `AdminLobbyService`; `GameClass.AiDifficulty`).

## 4. The in-game DM UI

**The game runs entirely in DMs.** Per human player two messages are tracked on `InGameDiscordStatus` (`InGameDiscordStatus.cs:5-14`): the static **character sheet** and the interactive **main game message**. All senders skip bots, web players, and `PreferWeb` players (`GameUpdateMess.cs:131-137` and every send/update guard like `GameUpdateMess.cs:101-121`) — toggling PreferWeb from the web (WEB-BACKEND.md §4) silences the Discord copy; `UpdateMessage` then reroutes any extraText into `WebMessages` instead (`GameUpdateMess.cs:1768-1776`).

- **Character sheet** (`GetCharacterMessage`): normally name, four stats and one field per visible passive. A Ziggurat-learned passive is forced visible and immediately triggers `UpdateCharacterMessage`, so its exact name and description appear for the Goblin owner in Casual and Pro without waiting for another sheet refresh. Dopa labels mechanical Intelligence as `IQ` and formats 7/8/9/10 as 200/209/218/228 (below 7 subtracts one each); his four visible fields are Макро, Взгляд в будущее, Permaban and one Законодатель меты field whose description changes after selection, while the four hidden tactics produce no fields. TheBoys is the exception to normal hidden-passive omission: each hidden ultimate/combination or СуперМудень-locked member is rendered as an anonymous `🔒 / Способность закрыта` field, never exposing its name or description; an unlock replaces that slot on a later update. Its ARAM page applies the same anonymous lock rule. Sakura renames the stats Сексуальность/Грубость/Скорость/Нытье. unknown_bug instead receives a green terminal embed whose full-size image field points at the deliberately absent 404 avatar URL—there is no valid thumbnail, placeholder or generated replacement—plus `Name: unknown_bug`, four exact `ERR: cant_get_stat` lines and each unchanged passive description formatted as a C# source/comment module. Sent/updated via `SendCharacterMessage`/`UpdateCharacterMessage`; Dopa formatting uses `CharacterClass.GetIntelligenceString`; Ziggurat refresh is in `CharacterPassives.ResolveGoblinZigguratBuild` (M207).
- **Main message** is rebuilt by `UpdateMessage` switching on `MoveListPage`: 1 = FightPage + game buttons; 2 = RESERVED (empty; legacy logs page); 3 = LvlUpPage + level-up select (+ the decorative disabled `crutch` button "Riot style choice" for round-9 Дизмораль); 4 = debug (commented out); 5 = AramPickPage + reroll buttons; 6 = DraftPickPage + pick buttons. An ordinary Ктулху game opens page 1 on round 1 with its `∞` character sheet and only `Выбрать адепта` plus End Game; pressing it moves that owner to page 6 and opens the existing four-option `Выбери адепта` ritual. Page 6 also hosts the blocking `Зов глубин` yes/no prompt when all four adepts already exist. On Dopa's second upgrade page, the stat copy/options are replaced by the four metas and no stat is awarded. Madara's hidden fifth passive is explicitly omitted from ARAM as well as the ordinary character sheet/draft (`GameUpdateMess` `GetGameButtons`/`DraftPickPage`/`GetDraftPickButtons`/`LvlUpPage`/`GetLvlUpMenu`; `GameReactions.GetLvlUp`).
- **FightPage anatomy** (`GameUpdateMess.FightPage`): title "King of the Garbage Hill", footer = `GetTimeLeft` (`(N/300с) | Версия…`, plus `Ожидаем других игроков •` when ready; mylorik/DeepList get the `(x+х)*19` gag); description = global logs (admin-hidden snippets stripped for non-admins) + stat/resource block + the leaderboard. Character-derived target/status markers are viewer-scoped: owners see the enemies, positions and objectives their own kit tracks, while affected opponents, allies and unrelated viewers receive no identifying icon. This includes Goblin mines/Ziggurats, DooM nests, sealed Мадара, Salldorum's fixed-cell 🥤, ScamRat's active-card `🖥️` and Napoleon/Support alliance annotations. TheBoys alone sees 🦸 on current Butcher targets and ☣️ on every row infected by its own Смертельный вирус; affected players, unrelated viewers and admins receive neither marker. Homelander alone sees `🔥N%` after each enemy name, plus `👁️` on every enemy who revealed him through Скромность; spending the laser returns that enemy to `🔥0%` because it can be charged and fired again. Итачи alone sees `👁️` after the enemy currently under **Глаза Итачи** and `🛑` after every caught enemy whose technique has ended (the technique never works on them again); the affected player and other viewers receive neither marker. ## 6. Dispatch & round resolution

All in-game components land in `GameReaction.ReactionAddedGameWindow`:

1. **Ownership guard**: the click must come from a player of a live game whose tracked `SocketGameMessage` id equals the clicked message (`GameReactions.cs:137-142`) — clicks on other messages fall through to the other three handlers.
2. **Debounce**: < 700 ms since `LastButtonPress` → ephemeral `Ошибка: Слишком быстро! Нажми на кнопку еще раз.` (`GameReactions.cs:144-150`).
3. **Paused-transition gate**: while `GameClass.IsRoundTransitionPaused`, only IDs beginning `gordon-hl3-freeze:`, `gordon-hl3-postpone:` or `gordon-hl3-release:` reach decision dispatch; every other forged component receives the ephemeral `Halflife 3: ожидаем решение Гордона Фримена.`. The suffix must parse as the current decision serial and the choice must match the current decision kind, otherwise the click receives `Это решение по Halflife 3 уже устарело.`. The rendered `gordon-hl3-wait` component is already disabled (`GameReactions.ReactionAddedGameWindow`; `GordonFreeman.ResolveHalfLifeDecision`).
4. Switch on custom-id (`GameReactions.ReactionAddedGameWindow`), §5 table. `IsSolo` short-circuits re-renders when the resolution is imminent.

**Attack trace** (`GameReactions.cs` `HandleAttack`): an untransformed round-1 Ктулху with a free adept is rejected before Block/attack parsing and its rendered page exposes only `Выбрать адепта`. The fixed `nechto-attack` value is otherwise recognized before any Guid/place parsing and queues the actor in `CthulhuState.PendingNechtoAttackers`; Change Mind removes that pending request. `SubmitNechtoAttack` independently rejects round-8 Мадара, and his attack menu omits the sentinel while he waits. Every other option is parsed as the target's player Guid — or, for bots/web (`IsAutoMove` trick, WEB-BACKEND.md §8), by leaderboard place — then records `WhoToAttackThisTurn`, the state the ordinary fight loop consumes. Before recording, sealed Madara is rejected as actor or target with `Игрок запечатан`, round-8 Madara is rejected as actor, an initialized Naruto sibling is rejected with `Наруто не могут нападать друг на друга.`, and `Tigr.IsRoundTenBanned` rejects both Тигр and a top-1-Permabanned Dopa through the shared round-10 target gate. The remaining guards are pickle-Rick auto-confirm, Клинки хаоса splash, Weedwick/DeepList pets, round-10 Butcher ban, СОсиновый кол, self-attack and Макро first-of-two. If Dopa's second Макро action selects the **same** target as the first, `Dopa.ActivateDuplicateTargetSkip` clears both attacks, sets the whole turn to confirmed Skip and records the target's identity in Dopa's predictions; for a Tier −1 or `Монстр без имени` target, a strict bot reuses its existing admissible inference hypothesis or, if none exists, takes the strongest public-catalog prior, while only a human falls back to a random **wrong** public prediction. `EnforceDuplicateTargetSkip` keeps all later forced-fight layers skipped. A distinct second action instead becomes ready with `Вы напали на игрока {name}`. Submitted Нечто fights resolve after ordinary fights against a fresh isolated 10/10/10/10, 0-Justice snapshot; a win awards 2 regular points, and the entity never enters `PlayersList` or passive dispatch (`Dopa.ActivateDuplicateTargetSkip`/`EnforceDuplicateTargetSkip`; `Cthulhu.SubmitNechtoAttack`/`ResolveNechtoAttacks`; `DoomsdayMachine.CalculateAllFights`).

**Resolution is timer-driven** — clicking never resolves a round. `CheckIfReady` ticks every 100 ms: dead players auto-ready solely so they cannot stall, but their queues are cleared and they do not act, force fights or dispatch ordinary passives. Humans receive the ordinary timed refreshes/readiness floor. A live round 8 containing Madara, at least one human and a living strict bot has an additional hard 30-second scene gate. The exact Madara prediction is already installed for every eligible strict bot when round 8 starts and cannot be replaced; only after the gate opens do bots spend level-ups and choose a normal AI action. Headless all-bot simulations do not wall-clock wait. During a Kratos event Kratos and unknown_bug retain their actions; every other queue is cleared and blocked before fight calculation. Bug's attack menu and Block button therefore stay enabled after round 10 (`CheckIfReady.TickAsync`; `Madara.EnforcePostRoundSevenBotPrediction`; `DoomsdayMachine.EnforceKratosEventActions`; `GameUpdateMess`). Once readiness/timeout gates pass, idle-human/Dopa automoves, living bots and legal forced-action layers run before `CalculateAllFights`. Теневые clones force Attack at every AI level; if every authoritative candidate is rejected they Skip, and the late readiness safety path also cannot auto-Block them. The original Naruto keeps the ordinary Block/Harem choice whether human or bot (`Naruto.CanChooseBlock`; `BotsBehavior`; `GameReactions.AttackOrSkipInsteadOfBlock`). Gordon's bot/Auto Move Block choice announces Halflife 3 while possible; after that it retries eligible attack targets and Skips only when every candidate is rejected, never submitting an actual Block (`GameReactions.HandleAttack`; M66). A failed human Halflife 3 attempt—or the first successful attempt with a transfer left—pauses only that game's transition for up to 20 seconds after fight/passive resolution but before score settlement and next-round reset. The decision click resumes the saved continuation; failure timeout defaults to Freeze, successful review to Release, and the readiness loop keeps processing other games meanwhile (`GordonFreeman.PrepareHalfLifeSettlement` / `ResolveHalfLifeTimeout`; `DoomsdayMachine.ResumePendingRound`; `CheckIfReady.TickAsync`).

**Вечное Цукуеми false-turn boundary:** after round-9 settlement advances the counter to round 10, `Madara.CaptureEternalTsukuyomiRoundOpening` freezes the authoritative order/scores/deaths/winner before `HandleNextRound` without finishing. The complete round-10 action UI remains available. After readiness, submitted pairs are saved for personalized illusions and all real queues become Skip; combat and ordinary round-10 settlement never execute (`Madara.PrepareEternalTsukuyomiRound`; M209).

Message edits are serialized per player through an embed queue with 200 ms spins (`ModifyGameMessage`, `HelperFunctions.cs`); transient side-messages auto-delete at round end (`SendMsgAndDeleteItAfterRound`/`DeleteItAfterRound`). Before sending, the localized payload is normalized to Discord's server-side rules (M49): whitespace-only field values become `\u200b`, the embed is trimmed to the 6000-char total by truncating its longest fields (description as last resort), and select menus with zero options — plus any then-empty action rows — are stripped (`SanitizeEmbedForDiscord`/`RemoveEmptySelectMenus` in `HelperFunctions.cs`). `FightPage` additionally skips whitespace-only 1020-char log chunks instead of adding them as fields. Its fight-row normalizer rewrites only rows that contain both the war marker and `⟶` result delimiter; a partial or malformed row passes through unchanged instead of aborting the whole DM update (`GameUpdateMess.HandleIsNewPlayerDescription`; M65). Personal-log entries must be `\n`-terminated: `AddInGamePersonalLogs` merges same-source consecutive entries by string surgery and `SortLogs` parses `Обмен Морали`/`Класс` totals out of the text (with `int.TryParse` tolerance), so a newline-less entry glues onto the next one and corrupts both (M48).
