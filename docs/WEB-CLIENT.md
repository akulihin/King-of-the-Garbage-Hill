## 1. Stack & build

- Vue 3.5 + TypeScript + Pinia 2 + vue-router 4, SignalR client `@microsoft/signalr` 8, icons `lucide-vue-next` (package.json dependencies). Scripts: dev = vite, build = vite build, serve = vite preview, `test:empires` = the retained Empire Vitest suite, `test:empires:e2e` = retained Empire Cypress scenarios, type-check = vue-tsc (broken in this environment — **`pnpm build` is the verifier**, per AGENTS.md), lint = eslint --fix.
- One Vite build outputs **straight into the backend's wwwroot**: `outDir` ../../King-of-the-Garbage-Hill/wwwroot with `emptyOutDir` (`vite.config.ts` `build`) — deploying the backend ships one HTML host plus the lazy product chunks.
- Dev proxy forwards `/api`, `/gamehub` (ws), `/art`, `/sound` to the **production EC2 box** http://3.65.44.127 (`vite.config.ts:24-44`) — local dev talks to prod by default; a commented localhost:3535 alternative sits in the .env file. Prod build uses same-origin: .env.production sets empty VITE_API_HOST and VITE_SIGNALR_HUB=/gamehub.
- `main.ts` is a small host selector. `apps/registry.ts` matches the URL and dynamically imports one of five application modules before Vue, Pinia or any router is created. Every module gets a fresh application/Pinia instance from `platform/bootstrap.ts`; only router-owning products install vue-router.
- Automated test source is **Empire's Endgame only**. Its integrated gate is `bash tools/test-empires-endgame.sh`; `--unit-only` and `--e2e-only` select a layer. KOTGH, Battleship, 99LC, network Clash and shared/platform code must not gain specs, tests, Cypress files, test directories or backend test projects/files. `bash tools/audit-test-policy.sh` enforces the allowed locations and common naming conventions and is part of `tools/verify-docs.sh`.
- New browser copy comes from root `Localization/*.messages.json`. `messageCatalogPlugin` rejects duplicate JSON properties before parsing, then validates product prefixes, `ru`/`en`, `public|owner|server` visibility and equal placeholder occurrences before serializing **only public messages** into `virtual:message-catalogs` (`vite.config.ts` `messageCatalogPlugin`; `platform/localization/messages.ts`). The old `publicLocalizationPlugin` remains a separate legacy adapter: it emits `virtual:public-localization` for arbitrary historic strings/replays, case-insensitively removes private character/passive terms and applies the catalog's validated `browserPrivate` section/key exclusions before Rollup sees them (`vite.config.ts` `publicLocalizationPlugin`; declaration `virtual-public-localization.d.ts`).
- Gotcha: `VITE_API_BASE` is read in two places but **never defined** in any env file — it resolves to '' so fetches stay relative (`replay.ts:11`, `Lobby.vue:9`); works only because of the proxy/same-origin setup.

## 3. Identity & session (client side)

Two login paths in `LoginProcess.vue`: a numeric **Discord User ID** input validated `/^\d+$/` with a "Copy User ID via Developer Mode" hint, or a **web username** (max 32 chars). Its buttons use the parent/store busy state and an inline ARIA alert, so a failed initial transport start re-enables a visible retry instead of leaving the login poisoned (`LoginProcess.vue:1-87`; `App.vue` `connectAndAuth`/`connectAndAuthWeb`/`handleWebLogin`). `App.vue` connects + authenticates and persists `discordId`, or lets the server mint a web account; the store saves `kotgh_web_id`/`kotgh_web_username` when `WebAccountCreated` arrives (`game.ts:317-339`). A root reload restores either saved identity silently, without replaying the three-second first-login success interstitial; an explicit login still shows that confirmation (`App.vue` `restoreSavedSession`/`connectAndAuth`/`connectAndAuthWeb`). The `AuthenticatedSession` payload also carries the account's normalized `language`; the store applies it through shared `setLocale`, making the server value authoritative once an account is known (`signalr.ts` `AuthenticatedSession`; `game.ts` authentication callback). There is no password — see the trust model in WEB-BACKEND.md §2.

## 4. SignalR client (`signalr.ts`)

Singleton `signalrService` (`signalr.ts:1644`); hub URL from VITE_SIGNALR_HUB, default /gamehub (`signalr.ts:3`).

- **Lifecycle**: `connect()` builds the connection `withAutomaticReconnect` at 0/1s/2s/5s/10s/30s and registers every handler (`signalr.ts` `connect`). A failed first start or exhausted disconnected instance is stopped and discarded so explicit login can build a fresh transport; reward and network-Clash invokes additionally require an authenticated session, not merely a connected socket (`requireConnected`). **On reconnect it re-authenticates with the remembered ID and re-joins the remembered ordinary game.** If an authoritative `ClashState` previously established `_currentClashGameId`, it also calls `JoinClashGame` and `RequestClashState` after re-authentication; `LeaveClashGame` and full `disconnect()` clear that memory (`signalr.ts` reconnect/Clash wrappers).
- **Server events → store** (handlers assigned in `useGameStore.connect()`, `game.ts:159-382`): quest and achievement state retain their existing recovery behavior; `StoreState` replaces the full owner-only shop snapshot after reads and durable transactions, clears the matching busy/error state, and mirrors its ZBS balance into an already-loaded quest board (`game.ts:284-293`). Re-authentication refreshes the shop only after that surface has been opened once (`game.ts:341-349`). `Authenticated` applies the persisted account language; `LanguageChanged` applies the server-confirmed replacement. The `setLanguage` wrapper requires the hub to return `ru` or `en`, so a failed save rejects and `App.vue` restores the previous selector value (`signalr.ts` `AuthenticatedSession`/`setLanguage`; `game.ts` `setLanguage`; `App.vue` `changeLocale`).
- **Curated-lobby events**: callbacks mirror `AdminLobbyState`, `AdminLobbyDirectory`, `AdminLobbyPresence`, `AdminLobbyReserved` and `AdminLobbyGameStarted`; all snowflake IDs remain strings. The ten invoke wrappers are `createAdminLobby`, `requestAdminLobbyState`, `requestAdminLobbyDirectory`, `requestAdminLobbyPresence`, `adminLobbyInvitePlayer`, `adminLobbyAddBot`, `adminLobbySetCharacter`, `adminLobbyRemoveSlot`, `adminLobbyStart` and `adminLobbyCancel` (`signalr.ts` admin-lobby types/callbacks/wrappers).
- **Network Clash events/wrappers:** callbacks mirror `ClashLobby`, `ClashState`, `ClashGameCreated`, `ClashGameJoined`, `ClashResolution`, `ClashCatalog` and personalized `ClashMyActiveGame {gameId|null}`. A generic `ActionResult` whose action begins `clash` is additionally routed to `onClashActionResult`; generic `Error` also reaches `onClashError` so create/join/membership failures do not leave a page latch busy. Wrappers mirror all eighteen hub methods: lobby/create/join/leave/state/catalog plus set-configuration, set-army, ready, place/remove/confirm setup, reinforcement, active, continue and forfeit (`signalr.ts` Clash callback and wrapper blocks; WEB-BACKEND.md §4).
- **Invoke wrappers** otherwise mirror the hub 1:1 (WEB-BACKEND.md §4), including Gordon's `announceHalfLife3(gameId)`, `wakeGordon(gameId)` and serial-protected `resolveHalfLife3Decision(gameId, decisionSerial, 'freeze'|'postpone'|'release')` (`signalr.ts` Gordon actions), Ктулху's owner-only round-1 `beginAdeptChoice(gameId)` plus `depthsCallChoice(gameId, agree)` pre-game answer, the character-store request/adjust/reset methods, and account-level `requestDoomFortress`/`equipDoomModule`.

## 6. Stores (Pinia)

**`useGameStore`** (`game.ts:54`) — the core store.
- State refs (`game.ts:57-97`): identity/game/meta state plus quest state/loading/error/reroll ID, resumable `lootBoxResult`, store-owned loot-modal priority, achievement board/full celebration queue/loading/acknowledgement-error state, character-store snapshot/loading/action/error state, character list and `doomFortressState`. Curated staging adds `isGodAdmin`, `adminLobbyState`, `adminLobbyDirectory`, `adminLobbyPresence` and `godReservation`; logout resets all five.
- Getters: `myPlayer` by myPlayerId — null for spectators (`game.ts:96-103`); `opponents` (`game.ts:105-110`); `isMyTurn` = not paused, not awaiting Ктулху's adept action, not ready and not skip, with round-8 Madara always locked false (`game.ts` `isMyTurn`); `roundTimeLeft` = turnLength − timePassed; `isInGame`, game/admin flags and character helpers. `isTerminalMode`/`myTerminalState` and `isDeepSession`/`depthsCallPromptActive` are generic owner-only selectors over the matching `Player` projection; components never detect either private presentation by a character/passive string (`game.ts` selectors). `beginAdeptChoice()` and `depthsCallChoice(agree)` forward the current game ID to their SignalR wrappers.
- `connect()` (`game.ts:154-364`) wires every SignalR callback; the `GameState` handler additionally diffs own stats for sounds, **auto-joins Blackjack when newly dead to Kira**, and captures full finish-time achievement entries once per game (`game.ts:175-238`). Quest/board callbacks restore server-held Daily Quest/loot/achievement state (`game.ts:242-275`); authentication hydrates both reward families and accepts the independent hardcoded-access `isGodAdmin` flag. Curated-lobby actions and callbacks update their complete state/directory snapshots while presence replaces only the three ID arrays (§4).
- Action wrappers mirror the hub and layer client SFX: block plays block + Geralt meditation + turn-10 layer, levelUp records `pendingLevelUp` for sound resolution, and moral exchanges play once per round. Gordon's wrappers reject announce/wake locally during a paused transition and submit the server-supplied decision serial with the release choice (`game.ts:525-545`); the backend remains authoritative.
- Daily Quest requests expose dedicated loading/error state; one in-flight request queues at most one trailing refresh (so a call spanning UTC midnight cannot strand yesterday's board), and `rerollDailyQuest` keeps the chosen card busy until the server sends its durable replacement (`game.ts:685-717`; hub wrappers `signalr.ts:1512-1518`). Loot wrappers keep acknowledgement explicit: `openLootBox` invokes `OpenLootBoxV2`, waits at most 12 s for the server event and exposes the idempotent retry path; acknowledgement refreshes current inventory, and `clearLootBoxResult` removes only the matching result (`game.ts:719-767`; wrapper `signalr.ts:1520-1526`). Achievement dismissal snapshots the IDs shown but **keeps the popup/queue visible** while saving; only a successful selective acknowledgement removes them, while failure stays inline and retryable (`game.ts:795-827`). Logout hard-resets quest/reward/modal/ack state (`game.ts:396-444`).
- Character-store wrappers keep one account transaction in flight, expose page-local loading/errors, and rely on each returned full snapshot as the durable confirmation; requests, ±1/±10 changes, one-character refunds and refund-all live at `game.ts:815-873`.

**`useReplayStore`** (`replay.ts:122`) — replay playback. State: replayData/raw currentRound/currentPlayerIndex/currentFightIndex (`replay.ts:122-129`). The round-window adapter detects format v2 versus legacy boundary files (`replay.ts:21-54`): v2 uses actual round numbers and explicit `preFightPlayers`; legacy raw URL key K remains K for old deep links but is displayed as logical combat round K−1 and obtains pre-fight state from the preceding boundary (`replay.ts:133-166`). `computedGameState` (`replay.ts:177-269`) **reconstructs a full GameState** from the chosen round + player perspective so normal in-game components render replays unchanged: `buildShiftedPlayer` takes fight-facing actions/character/passive state from pre-fight and settled score/place/death/breakdown from the atomic result, discarding its next-round status/log buffer (`replay.ts:56-120`). V2 appends only explicit HandleLastRound personal/global suffixes (`signalr.ts:1001-1019`); legacy final files retain their inseparable raw final personal buffer (`replay.ts:48-54,165-166,208-258`). Other players' private blocks remain stripped (`replay.ts:199-240`), and replay state is finished/admin-visible (`replay.ts:243-268`). Because captured private snapshots reflect the original player's presentation locale (`ReplayService.cs:301-339`), the legacy Vue boundary re-localizes canonical and older mixed phrase records for the current replay viewer (`Web/VueClient/src/i18n.ts:146-196`). `loadReplay` fetches the anonymous REST payload and starts on the final playable logical round (`replay.ts:273-295`).

**`useBattleshipStore`** (store/battleship.ts) — minigame state/lobby/placement/combat/VFX state with its own signalr callback wiring; independent of the main game store (§12).

**`useClashStore`** (`store/clash.ts`) — independent network-Clash state. It owns lobby/game/catalog snapshots, the personalized `myActiveGameId` resume pointer, derived self/opponent/board/catalog maps, navigation handoff, busy/error state, revision-tagged mutation wrappers and the combat timeline's visual overrides. Each mutation sends the latest public `expectedRevision` plus a fresh UUID `commandId`; private setup edits can therefore share one revision until confirmation publishes the row. A failed Clash `ActionResult` surfaces the server error and requests authoritative state because rejected mutations do not trigger a normal state push. Page mount/unmount installs and removes only the Clash callbacks. Resolution identities `{gameId}:{revision}:{clashNumber}` suppress duplicates; changing games clears the resolution cache. A generic public `ClashLobby` update never overwrites `myActiveGameId`; only the personalized `ClashMyActiveGame` event can set or clear it.

## 7. Pages & flows

- **Fight Calculator** (`FightCalculator.vue`, route `/fight-calculator`): local-only combat lab for two teams of up to six units. Each unit can configure HP, movement speed, primary/secondary/dagger weapons, mastery, helmet/mail/padding/plate armor and talents. The seeded engine (`features/fight-calculator/engine.ts`) resolves mirrored slots, free-opponent fallback and survivor collisions while logging range, fatigue, techniques, penetration, armor/weapon degradation and status effects step by step. The baseline catalog (`features/fight-calculator/catalog.ts`) transcribes the supplied weapons-and-armor spreadsheet; the Balance dialog can edit mechanics/catalog values and add custom weapons, armor or talents. Named profiles, their balance copies and team layouts stay browser-local under `kotgh_fight_calculator_profiles_v1`; this surface has no SignalR or backend contract.

## 12A. 99 Last Chances prototype

The `/99lc` surface is a self-contained browser prototype built on Vue plus a native Canvas 2D engine under `features/last-chances/`; it does not call REST, SignalR or the account economy. The engine renders one configured 16:9 room at a time through a fitted diamond-isometric projection below the HUD. `projection` derives that room's world→screen basis and is the single authority for it: **both world axes share one scale**, so a world unit covers the same screen distance whichever way a body moves, and `entityScale` is that same horizontal scale. `worldToScreen` maps world X/Y onto the two opposing isometric axes from it and `screenToWorld` is its inverse, clamped to the room; floors, hazards, telegraphs, traces and world-space effects share that projection. Because the room is drawn to scale, a 16:9 arena projects as an elongated rhombus rather than a symmetric diamond, still spanning exactly the fitted `diamondWidth` × `diamondHeight` box and still centred horizontally; floor-grid cells are therefore uniform. The residual screen-speed difference between the horizontal and vertical screen directions is the projection's `1.55` foreshortening and is intended. Entities are depth-sorted by world `x + y` and drawn above their projected ground anchors, while obstacle `elevation` raises each top face and exposes its side faces. Every executed action debits `staminaCost` or the global `stamina.attackCost` (2), and an action the player cannot pay for is refused outright — no combo step, cooldown, rhythm state or collider is touched, the engine stamps `player.staminaRefusedAtMs`, emits the existing `blocked` haptic and forces a snapshot so the HUD blinks the bar. Skilled play refunds part of the debit but never waives it: continuing an unbroken chain inside `stamina.comboWindowMs` refunds `comboRestore` (2), and acting with the hand that did not act last additionally refunds `handAlternationRestore` (5), so a chained tap is a wash rather than free. Regeneration is `stamina.regenPerSecond` (5) while any enemy is noticing, alerted, chasing or attacking, and `stamina.outOfCombatRegenPerSecond` (25) otherwise; the same predicate defines "in combat" for mental pressure, and the cleared-room loop regenerates too so exploring is never stalled. `Лёгкие бегуна` multiplies maximum stamina by 1.25 through `effectivePlayerStats`, `Второе дыхание` adds a flat 10/s, and the `Дыхательная упряжь` outfit doubles restoration from every source — passive regeneration and both attack refunds alike. Maximum stamina is a full `LastChancesStats` member so it flows through the snapshot and Builder, but every shipped tier erodes it by 0. Two full-screen overlays translate the vitals into ambience below the HUD: `.lc-breath-fog` fogs the four corners and shortens its breath cycle from 5,200 ms to 1,400 ms as stamina drains past 60%, and `.lc-mental-vignette` closes a purple edge vignette inward as mental health drains past 80%. Both curves are pure functions so they cannot drift from the bars, both are CSS-animated rather than JS-stepped because snapshots arrive at 20 Hz, and reduced motion keeps them static at the same intensity (`types.ts` `LastChancesStaminaDefinition`/`LastChancesStats`; `config.ts` `validateStats`/`backfillStaminaFields`; `engine.ts` `staminaCostFor`/`settleStaminaForAttack`/`refuseForStamina`/`updateStamina`/`combatPressurePerSecond`; `vital-atmosphere.ts` `resolveLastChancesVitalAtmosphere`; `pages/LastChances.vue`).

Enemy definitions assign distinct `creep`, `cockroach`, `standard`, `elite` or `boss` roles plus melee, projectile, heavy-area, leap or telegraphed-zone attacks. Creeps and cockroaches may attack concurrently, while every other role shares one attack slot so surrounding enemies continue to reposition instead of striking simultaneously. A short release of a tap-parry opens its collider immediately instead of waiting for the 260 ms double-tap classifier; if that provisional window actually parries an attack, a queued compound gesture from the same input is consumed, while an unused window is canceled when the compound gesture resolves. This keeps the visible 95–190 ms enemy parry windows reactable without giving every double tap a free overlapping parry. Shipped Knife-spiders use `behaviorVersion: 2`: the 48-HP/2-armor creature renders from the transparent realistic horror sprite `public/99lc/spider-knife-v2.png`, runs at 1.65× its base speed with a changing zigzag, orbits at 82 units with seeded random direction changes and periodic knife strikes, and has a 68% reaction chance to sidestep a fresh player attack before approaching from another side. When separation reaches 220 units it starts a direct locked leap only if no living mob already blocks the player segment; once airborne it does not steer, so a later mob, obstacle or arena edge can still intercept it. Any player attack collider that meets the airborne creature reflects its incoming velocity around the player-contact normal, biases the result with the swing direction and launches it away at no less than 1,250 units/s. The reflected body deals the configured ×4 damage to another mob. Reflection costs 10% maximum HP, every later collision costs another 10%, and impact with a mob or solid surface embeds/stuns it for the 2,200 ms all-side capture window; an ordinary completed or player-hit leap exposes only 170 ms. Builder `behaviorVersion: 1` preserves the original long telegraph, locked vector/facing and rear-only missed-leap capture path. The non-cockroach creeps Слуга and Бегущий степлер have enlarged collision/render bodies and respectively 34/26 HP; Running staplers remain projectile creeps. Heavy elites render their larger danger radius.

Shipped Invisible wolves also use `behaviorVersion: 2`, which replaces the shared notice→alert→chase path with a hunt the wolf owns end to end, visibility included. It never enters `alerted` and never shows the `!!` marker: once its ordinary vision cone has noticed the player it goes straight to stalking, holding its runtime `state` at `idle` so the shared `enemyVisible` rule keeps it off the screen. While stalking it walks to a post behind the player's aim and waits there; when the player's aim swings onto it the wolf loses its accumulated patience and slides around to the other side, so it can only build up a run from behind. A committed approach is still unseen, but turning to face the wolf calls it off at any point — that is the counterplay, and it holds regardless of where the wolf is standing because every decision reads one dot product against the player's aim. The pounce itself is the ordinary heavy attack, so the wolf becomes fully opaque for the whole 780 ms windup with its 145 ms parry window and red danger ring. Afterwards it stays visible and backs off for a fixed delay before it may vanish again, and any landed hit, parry or pin pins it on screen as a plain elite for as long as the reveal lasts. Because a hidden wolf's `state` stays `idle`, mental pressure is charged from its hunt phase instead: a wolf that has committed to a run presses the player's mind exactly as the pre-stalker wolf did, while one that is merely stalking presses nothing, which is its equivalent of not having noticed you. Builder `behaviorVersion: 1` restores the shared elite path exactly. Its model is drawn procedurally as an upright billboard mirrored by screen-space facing — torso, low-slung neck and wedge skull, ears, tail and four gaited legs, crouched while stalking, coiling and then unspooling through a windup, upright at a run. While hidden it is not the blanket 7% fade every other invisible body gets: the method draws a doubled refraction outline that brightens as the wolf commits, plus eye glints that only catch the light when the wolf is looking roughly at the player. That is the whole tell budget — a player who turns around can find it, a player who never turns cannot.

The rest of the room is drawn the same way. Obstacles are the tier's «Живые стены» literally: the authored rectangle is load-bearing for movement, line of sight and every collider test, so nothing in the drawing moves the silhouette — the life is entirely inside it, as a slow breath that swells the lit face, veins creeping across the top from a layout hashed off the obstacle's own coordinates so a wall looks the same every frame, and ribs banding the front. The two hazard kinds no longer share one coloured rectangle: spikes are a bed of blades that stand up on the active beat and sit nearly flush between beats, mental fog is a drift of soft shapes that thickens while it bites, and both are clipped to the authored footprint that the damage test uses so the drawing can never promise a safe pixel that is not safe. Turrets carry the shape they are named for — «Круг», «Квадрат», «Треугольник», «Ромб» — on a housing over a plinth and a barrel, with a lens that lights only while the turret still sees the player, which is the only thing that tells the four apart at a glance. Boss holes keep their authored shape exact, because the player is meant to learn which shape answers which, and gain a torn lip, strands crossing the dark and a rim that breathes. A weapon lying on the floor is drawn as itself — spear, chain, claws, Knife-spider, axe, katana, fang, or a generic blade for anything the Builder adds — so a dropped Axe is distinguishable from a dropped Katana without walking onto it. Projectiles are drawn as the thing that was fired, laid along their screen-space travel direction: the Running stapler throws a tumbling staple, the Curator a fluttering page out of its archive, turrets a finned bolt, the player a long shard. An incoming shot is marked by a red halo rather than the old red outline, because outlining line work erases the shape; anything unmodelled keeps the original ball and red ring. The model is chosen from a new `RuntimeProjectile.sourceId` (the firing definition's id, or `player`) — `sourceName` is a display name and is never matched on.

Every enemy is hand-drawn from its own procedural body rather than the primitive it used to be, and only the Knife-spider ships as a raster sprite. Two orientation rules cover them all. Anything that stands — Слуга, Стражник, Бегущий степлер, Химера, Исполин, Тень Куратора, Невидимый волк — is an upright billboard: it stands on its ground point and mirrors by the sign of its screen-space facing instead of rotating, because a rotated upright body reads as falling over in an isometric arena. Insects — Мать тараканов and Таракан — are drawn from above and really do rotate, the same convention the Knife-spider sprite uses. Every body is keyed to the single `color` the Builder exposes, mixed lighter or darker for depth, so recolouring an enemy recolours its whole model. Each one leaves its silhouette as the current path instead of an approximating ellipse, which is what `renderEnemy` then strokes — so the white outline, and the thick red one during a wind-up, trace the actual creature.

## 12C. Standalone network Clash

The production network Clash is a second implementation with a deliberately separate module boundary from §12B.1. Its source lives in `features/clash/`, `store/clash.ts`, `components/clash/`, `ClashLobby.vue` and `ClashGame.vue`; its independent app root and router live under `apps/clash/`, and it consumes the server-authoritative DTO/event stream described in WEB-BACKEND.md §10. It does not import the Empire's Endgame Clash catalog/engine, share its deterministic turn log, read campaign localStorage or settle campaign results. Empire's embedded Clash likewise never imports this network store or transport.

The state-driven screen flow is:

```
Lobby + army/config
  → parallel hidden front row
  → guest/host second row
  → guest/host third row
  → timed clash
  → guest/host reinforcement
  → alternating actives
  → timed clash … → Finished
```

`ClashGame.vue` maps the DTO phase through `clashPhaseKind`: `ClashArmyBuilder` handles the hand, `ClashDeploymentPhase` restricts clicks to the server's `requiredPlacementRow`, `ClashCombatPhase` combines the board and timeline, and `ClashBetweenPhase` handles one-click reinforcement/pass plus generic catalog abilities/morale. `ClashBoard` renders one aligned `width × (2 × length)` grid, reverses row order for the host perspective, horizontally accommodates the 10×5-per-side maximum and never invents content for a `unit:null` private cell. `ClashUnit` renders `/clash/art/units/{definitionId}.webp`, falls back to initials if art fails, shows HP/attack/speed/defense state and applies shared plus unit-family CSS attack/passive/death/advance treatments (`components/clash/`; `features/clash/visuals.ts`; `components/clash/clash.css`).

Combat presentation is an authoritative trace, not local combat simulation. `ClashResolution` arrives before the post-mutation `ClashState`; the store snapshots currently visible units and applies damage, death, movement, shield, dodge and bleed changes only when each event's server-provided impact offset fires. Pre-clash effective speed is also retained until the trace finishes, so a casualty-driven Легион bonus cannot flash its final value early. A setup row that becomes public in the same mutation as clash 1 is reconstructed backward from `finalUnits` plus the event trace so final HP/death/movement cannot flash early. `ClashActionTimeline` uses `startedAtUtc` to apply already-elapsed events immediately and schedule only the remainder, displays the latest twelve log rows, and completes at `durationMs`; `prefers-reduced-motion` applies the trace immediately. Attack timing therefore follows the server's speed bands rather than CSS duration. The server remains in `ResolvingClash` until the same nonterminal deadline, preventing reinforcement or bot actions during playback. A transport reconnect re-authenticates/rejoins/refreshes and resumes an unfinished trace at elapsed server time, including a terminal `Finished` trace; a `latestResolution` received after its duration or in a later input phase is not replayed merely because it remains in state (`store/clash.ts`; `ClashActionTimeline.vue`; `ClashBoard.vue`; `features/clash/visuals.ts`).

Privacy remains server-owned. The client renders only personalized `ClashState`: its own hand and unconfirmed placements, opponent rows only after confirmation, and no spectator fallback. The catalog and lobby carry no hidden match state; `ClashMyActiveGame` is sent only to the relevant caller/connections. Client `can*` flags, selectable-cell sets and disabled controls are affordances; every placement, active, pass and terminal action is revalidated by `ClashService`/`ClashGameEngine`. Network Clash has no browser match persistence or replay player: `_currentClashGameId` supports transport reconnect within a running SPA, while a full reload recovers only the server-held active ID through `RequestClashLobby` and then re-enters from a fresh authoritative state. It never rebuilds from a local command log, and a server restart remains unrecoverable (`store/clash.ts`; `signalr.ts`; WEB-BACKEND.md §10).

Network Clash has no retained Vitest/Cypress source. Verify changes with the frontend build, backend build, repository audits and targeted two-participant play/reconnect checks; Empire's own embedded-Clash specs remain part of the Empire-only gate and do not test this implementation.

## 13. Localization

New authored copy uses product-scoped stable keys in root `Localization/*.messages.json`. Each entry supplies `ru`, `en` and explicit `public|owner|server` visibility. `messageCatalogPlugin` validates the schema and equal placeholder sets during every Vite dev/build load, then exposes public entries only through `virtual:message-catalogs`; `platform/localization/messages.ts` resolves `message(key, arguments)` against the shared `currentLocale`. `apps/products.ts`, `App.vue` and `StandaloneGameShell.vue` use that boundary instead of repeating RU/EN ternaries.

Locale state itself lives in `platform/localization/locale.ts`, persists under `kotgh_locale`, updates `<html lang>`, and is shared by all five roots. Before authentication it defaults to the saved browser value or English. A current `Authenticated` payload replaces it with the normalized persisted account language; an absent field from an older server leaves the browser preference intact. Choosing RU/ENG calls durable `SetLanguage`, whose `LanguageChanged` event synchronizes every active tab for that account and whose active-game repush refreshes already-projected server text even when the selector was used in a lobby tab; a failed save restores the previous client value. Router-free 99LC/Empire change only their browser-local preference because they have no account connection (`App.vue` `changeLocale`; `signalr.ts` `AuthenticatedSession`/`setLanguage`; `game.ts` authentication callback).

`i18n.ts`, `virtual:public-localization`, the DOM observer and broad arbitrary-string rules remain deliberately installed as a **legacy compatibility adapter** for existing components, canonical logs and old replay payloads. The observer watches the mounted root's document body so teleported dialogs stay in the selected language. At build/dev transform time, `publicLocalizationPlugin` retains catalog-enabled character/passive content, removes records and phrase groups containing explicitly private terms in any letter case, applies validated `browserPrivate` section/key exclusions to private fallback text that contains no identifying term, and serializes only that sanitized legacy payload. Private Cthulhu sheet/choice fields and public Thing board/fight labels instead select server-derived paired display text through `localizedText`, leaving their canonical identifiers available for action and animation logic. New `|>PhraseV2<|` records decode their paired rendering; old `|>Phrase<|` records match passive title plus exact Russian body. The Chronicle still translates its complete legacy source before Discord markdown becomes HTML, and `MediaMessages.vue` selects paired DTO fields directly. Class labels/tooltips remain canonical in state and Russian passive/name strings remain backend dispatch keys. Do not extend this compatibility translator for new static copy; add a structured message key instead (`platform/bootstrap.ts`; `i18n.ts`; `vite.config.ts` `publicLocalizationPlugin`). Details: [LOCALIZATION.md](LOCALIZATION.md).

Achievement and Daily Quest metadata are deliberate typed exceptions: both DTOs carry paired names/descriptions, and their reward components select fields directly from `currentLocale` rather than translating identifiers (`signalr.ts:636-691,744-762`; `DailyQuestBoard.vue:98-166`; `AchievementBoard.vue:73-130`; `AchievementPopup.vue:100-108`). Related Achievement character names and Daily Quest IDs remain canonical identifiers.

Generated game stories carry separate RU/EN locale containers in one artifact; the global language CSS selects the visible block (`App.vue:487-490`). The backend requests each language independently, prompts for at most 250 words / 1,700 characters without post-generation trimming, and fills a failed or configuration-disabled side with a localized unavailable message, so one API failure cannot hide the other story or produce a blank locale view (`GameStoryService.cs:65-141,448-492,637-647`).
