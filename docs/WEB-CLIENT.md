- Dev proxy forwards `/api`, `/gamehub` (ws), `/art`, `/sound` to the **production EC2 box** http://3.65.44.127 (`vite.config.ts:24-44`) — local dev talks to prod by default; a commented localhost:3535 alternative sits in the .env file. ## 3. Identity & session (client side)

Two login paths in `LoginProcess.vue`: a numeric **Discord User ID** input validated `/^\d+$/` with a "Copy User ID via Developer Mode" hint, or a **web username** (max 32 chars). Its buttons use the parent/store busy state and an inline ARIA alert, so a failed initial transport start re-enables a visible retry instead of leaving the login poisoned (`LoginProcess.vue:1-87`; `App.vue:29-144,180-189`). `App.vue` connects + authenticates and persists `discordId`, or lets the server mint a web account; the store saves `kotgh_web_id`/`kotgh_web_username` when `WebAccountCreated` arrives (`game.ts:317-339`). `restoreWebSession` re-authenticates from those keys (`game.ts:822-833`). There is no password — see the trust model in WEB-BACKEND.md §2.

## 4. SignalR client (`signalr.ts`)

Singleton `signalrService` (`signalr.ts:1642`); hub URL from VITE_SIGNALR_HUB, default /gamehub (`signalr.ts:3`).

- **Lifecycle**: `connect()` builds the connection `withAutomaticReconnect` at 0/1s/2s/5s/10s/30s and registers every handler (`signalr.ts:1065-1180`). A failed first start or exhausted disconnected instance is stopped and discarded so explicit login can build a fresh transport; reward invokes additionally require an authenticated session, not merely a connected socket (`signalr.ts:1051-1081,1194-1260`). **On reconnect it re-authenticates with the remembered ID and re-joins the remembered game** (`signalr.ts:1182-1193`).
- **Server events → store** (handlers assigned in `useGameStore.connect()`, `game.ts:155-367`): every successful initial/re-authentication requests both quests and achievements, so the UTC Daily Quest board, balance, pity, inventory, resumable loot and queued celebrations recover together (`game.ts:316-338`). Quest state clears its own load/reroll error state, restores an unacknowledged loot result and starts one queued trailing refresh when a visibility/reset request arrived during the in-flight call; the achievement board rehydrates full queued cards; DooM Guy and battleship callbacks are unchanged (`game.ts:244-278,340-354`).
- **Invoke wrappers** mirror the hub 1:1 (WEB-BACKEND.md §4), including `doomRoll`/`doomChainsaw` (`signalr.ts:1418-1423`) and account-level `requestDoomFortress`/`equipDoomModule` (`signalr.ts:1538-1544`).

## 6. Stores (Pinia)

**`useGameStore`** (`game.ts:54`) — the core store.
- State refs (`game.ts:57-91`): identity/game/meta state plus quest state/loading/error/reroll ID, resumable `lootBoxResult`, store-owned loot-modal priority, achievement board/full celebration queue/loading/acknowledgement-error state, character list and `doomFortressState`; the DooM action wrappers and Fortress state remain in the same store.
- Getters: `myPlayer` by myPlayerId — null for spectators (`game.ts:96-103`); `opponents` (`game.ts:105-110`); `isMyTurn` = not ready and not skip, with round-8 Madara always locked false (`game.ts:112-116`); `roundTimeLeft` = turnLength − timePassed (`game.ts:122-125`); `isInGame`, game/admin flags and character helpers (`game.ts:127-152`).
- `connect()` (`game.ts:154-364`) wires every SignalR callback; the `GameState` handler additionally diffs own stats for sounds, **auto-joins Blackjack when newly dead to Kira**, and captures full finish-time achievement entries once per game (`game.ts:175-238`). Quest/board callbacks restore server-held Daily Quest/loot/achievement state (`game.ts:242-275`); authentication hydrates both reward families (§4).
- Action wrappers (`game.ts:348-573`) mirror the hub and layer client SFX: block plays block + Geralt meditation + turn-10 layer (`game.ts:354-364`), levelUp records `pendingLevelUp` for sound resolution (`game.ts:397-404`), moral exchanges play once per round (`game.ts:406-422`).
- Daily Quest requests expose dedicated loading/error state; one in-flight request queues at most one trailing refresh (so a call spanning UTC midnight cannot strand yesterday's board), and `rerollDailyQuest` keeps the chosen card busy until the server sends its durable replacement (`game.ts:685-717`; hub wrappers `signalr.ts:1510-1516`). Loot wrappers keep acknowledgement explicit: `openLootBox` invokes `OpenLootBoxV2`, waits at most 12 s for the server event and exposes the idempotent retry path; acknowledgement refreshes current inventory, and `clearLootBoxResult` removes only the matching result (`game.ts:719-767`; wrapper `signalr.ts:1518-1524`). Achievement dismissal snapshots the IDs shown but **keeps the popup/queue visible** while saving; only a successful selective acknowledgement removes them, while failure stays inline and retryable (`game.ts:795-827`). Logout hard-resets quest/reward/modal/ack state (`game.ts:396-444`).

**`useReplayStore`** (`replay.ts:122`) — replay playback. State: replayData/raw currentRound/currentPlayerIndex/currentFightIndex (`replay.ts:122-129`). The round-window adapter detects format v2 versus legacy boundary files (`replay.ts:21-54`): v2 uses actual round numbers and explicit `preFightPlayers`; legacy raw URL key K remains K for old deep links but is displayed as logical combat round K−1 and obtains pre-fight state from the preceding boundary (`replay.ts:133-166`). `computedGameState` (`replay.ts:177-269`) **reconstructs a full GameState** from the chosen round + player perspective so normal in-game components render replays unchanged: `buildShiftedPlayer` takes fight-facing actions/character/passive state from pre-fight and settled score/place/death/breakdown from the atomic result, discarding its next-round status/log buffer (`replay.ts:56-120`). V2 appends only explicit HandleLastRound personal/global suffixes (`signalr.ts:999-1017`); legacy final files retain their inseparable raw final personal buffer (`replay.ts:48-54,165-166,208-258`). Other players' private blocks remain stripped (`replay.ts:199-240`), and replay state is finished/admin-visible (`replay.ts:243-268`). Because captured private snapshots reflect the original player's presentation locale (`ReplayService.cs:301-339`), the Vue boundary re-localizes canonical and older mixed phrase records for the current replay viewer (`Web/VueClient/src/i18n.ts:146-196`). `loadReplay` fetches the anonymous REST payload and starts on the final playable logical round (`replay.ts:273-295`). Alignment fixtures cover legacy URLs/logs, v2 numbers, skip isolation, post-setup score/death/breakdown and final personal/global settlement (`replay.spec.ts:66-223`).

**`useBattleshipStore`** (store/battleship.ts) — minigame state/lobby/placement/combat/VFX state with its own signalr callback wiring; independent of the main game store (§12).

## 7. Pages & flows

- **Lobby** (`Lobby.vue`): polls only `refreshLobby` every 3 s, while Daily Quests refresh on authentication/mount, visibility return and the board's UTC countdown rollover (`Lobby.vue:150-177,216-237`). Its persistent Rewards hub shows live ZBS, pending box inventory, Rare+ distance/base Legendary chance, achievement completion/new badge and current-catalog totals (`Lobby.vue:248-358`). `DailyQuestBoard` renders the typed bilingual 2/3 daily + 3/3 mastery path, streak, explicitly explained 5/7 weekly journey, free reroll and all load/error/empty states; a replaced card is announced and receives focus after the old reroll button disappears (`Lobby.vue:365-375`; `DailyQuestBoard.vue:1-604`). The loot flow still owns modal priority and keeps its bounded retry/acknowledgement handoff unchanged (`Lobby.vue:41-144,378-394`).
- **Achievements** (`Achievements.vue` + `AchievementBoard.vue`): dedicated `/achievements` center (`router.ts:53-57`). It requests the board/character list, shows completion and reward summaries plus three nearest non-secret completions, then supports category/status/rarity filters and genuinely bilingual search across both EN/RU name, description and secret-hint pairs plus character names. Cards render character avatars, best-single-match progress, secret hints, rewards, rarity, unlock date, loading skeletons and retry/error states (`AchievementBoard.vue:22-197`; `AchievementBoard.vue:200-434`).
- **Game** (`Game.vue`, the main view): existing three-column play surface and action flows are unchanged. At finish, the game-over podium retains priority for ordinary motion; `prefers-reduced-motion` bypasses its fixed five-second gate and disables podium/confetti animation so the achievement reward is immediate (`Game.vue:609-632,1491-1497,3122-3132`). - **Spectate** (`Spectate.vue`): joins the game room read-only (`Spectate.vue:31`) and renders `FightAnimation` (`Spectate.vue:68`), `Leaderboard` (`Spectate.vue:80`), `BattleLog` (`Spectate.vue:96`); no action UI because the myPlayer getter is null.
- **Replay** (`Replay.vue`): public shared replay links bypass the app-wide login overlay (`App.vue:11-18,180-188`) and fetch the anonymous REST endpoint directly (`replay.ts:273-295`); no Discord or web account is required. Logical previous/next navigation skips the empty legacy opening boundary while preserving raw round query keys (`Replay.vue:310-368,449-459`; store navigation `replay.ts:297-330`), and enemy cards use the same aligned pre/result/log pair (`Replay.vue:193-212`).
- **Widget** (`Widget.vue`): parses `access_token` from the URL fragment (`Widget.vue:22`), scrubs it from history (`Widget.vue:31-32`), POSTs to the widget sync endpoint (`Widget.vue:38`) — the tail of the OAuth chain in WEB-BACKEND.md §12.
- **Home** (`Home.vue`): requests the authenticated account's Fortress state on mount and renders `FortressOfDoom` in the center column (`Home.vue:9-33`). The Fortress shows Rune/Shield/Mission/Gun, four slots each, unlocked category-filtered selects and the server-supplied module descriptions verbatim. Remaining reward count/live drop chance cover only standard placement rewards; special **Приручить дракона** appears after its separate unlock. Selection calls `equipDoomModule` (`FortressOfDoom.vue:1-54`).

## 9. Widget system (PlayerCard)

Widgets render **only for the owning player**: `passiveStates` computed returns the player's `passiveAbilityStates` (`PlayerCard.vue:158-161`), which the server only populates for isMe (WEB-BACKEND.md §7). Standard shell class pc-passive-widget with pw-header/pw-value markup.

Every original widget is its own help surface; there is no separate toolbar or permanent help row. A small `?` beside its title indicates discoverability, and the plain-language explanation expands only on widget hover, keyboard focus, or tap-to-focus. All 40 passive/special surfaces are focusable and expose the same text through `aria-description` (`PlayerCard.vue:1007-1749`). Copy, titles, state labels, Geralt demand controls and DooM module progress react directly to `currentLocale` through an explicit EN/RU map, because custom `data-widget-help` attributes are outside the DOM localizer (`PlayerCard.vue:167-215,960-1749`). Shared styling preserves readable hierarchy, ≥40 px action targets (44 px on narrow screens), responsive dense panels, themed character feedback and visible focus without idle vertical space (`PlayerCard.vue:3900-4095`). Animation-heavy states honor the `prefers-reduced-motion` fallback (`PlayerCard.vue:4097-4111`). DooM Guy, TheBoys, Salldorum and Geralt retain their character themes but use the same readability floor (`PlayerCard.vue:4330-4389`).

- **Special level-ups** use the dedicated `SpecialLevelUpPanel.vue` decision surface instead of stat `+` buttons. It covers DooM Guy modules, Goblin population upgrades/festival, Geralt oils, TheBoys members, Котики Justice, Вампур's no-stat consumption, Молодой Глеб's mandatory −1 and Seller's +10 Закуп; every card previews its exact result, labels reward/ultimate/max/one-shot states, and disables duplicate submission while the request is pending. Ordinary stat choices stay unchanged. Rick/Itachi/Salldorum/Darksci/Sirinoks retain normal stat buttons but receive an inline consequence note for their additional level-up effect (`SpecialLevelUpPanel.vue`; `PlayerCard.vue` `usesSpecialLevelUpPanel`/`levelUpConsequences`; `game.ts` `isLevelingUp`).
- **DooM Guy** gets a four-stage Rune/Shield/Mission/Gun rail at choice time and an always-on Fortress combat console afterward. The console reports the active module in every stage plus protected-stat reserves, objective progress/failure, Shield consumption, current Counter-attack targets/Shark stance, nest carriers, BFG/Railgun charge and all remaining Chainsaw trophy selections (including the two-pick Ближник case). Runtime **Дракон** state also reuses the existing dragon widget/theme. Missing/stale Fortress snapshots are shown as a recoverable state instead of misleading stat buttons (`SpecialLevelUpPanel.vue`; `PlayerCard.vue` `doomModuleStatus`). Let's Roll is a round-1 inline game action, and its state hides Moral controls.
- **Madara has no widget DTO**: the normal card branches on character name and omits all four resist/quality rows plus Moral, Skill, target and Moral exchange; the server never supplies level-up points or prediction catalogs. ## 12. Battleship client

The standalone minigame uses BattleshipLobby.vue / BattleshipGame.vue / BattleshipSpectate.vue (routes §2) and its own `useBattleshipStore`. `BattleshipGame.vue` is the shared shell: lifecycle, keyboard handling, header, overlays, error toast and forfeit dialog. Phase UI is split into LobbyPhase, ArmySelectPhase, FleetBuildPhase, PlacementPhase, CombatPhase and GameOverPhase; combat and boarding intentionally share CombatPhase. `BattleLogPanel.vue` is the minigame log, so it no longer collides with the main-game `BattleLog.vue` basename.

`battleship.css` supplies the scoped semantic visual system: glass cards, buttons, chips, ambient page layers and phase accents all resolve through the app theme variables rather than a separate pirate palette. Boards stack below 900 px, compact further on phone widths, action bars scroll, and controls retain touch-sized targets. `BsIcon.vue` owns chrome icons while battleship-icons.ts remains the high-volume ship/weapon/cell glyph catalog. Keyboard: Escape cancels summon deployment, Space rotates placement, and digits 1–9 select available weapons (`handleKeydown` in BattleshipGame.vue).

Combat mounts a `VfxCanvas` over each `.board-stage`. Each canvas observes its rendered size and measures real cells to derive origin and pitch (`VfxCanvas.vue:7-65`); the store's shot handshake delays hit/miss effects until the local projectile reaches impact, with an immediate fallback for opponent shots, reduced motion or an unmounted canvas (`CombatPhase.vue:430-464`; `battleship.ts:350-402`). Board diffs add freeze, devastation and Brander effects. Phase-change, turn-start, weapon-selection and explosion sounds are live; win/lose and the layered first-win reward cue belong to the focus-trapped GameOverCelebration modal.

The victory modal derives shots, accuracy and ships sunk from client-side `ShotResult` counters because the opponent fleet stays hidden in player DTOs; counters reset on game ID change (`battleship.ts:102-105,291-302,350-366`). The server-provided `myEndReward` adds the durable W/L, daily streak and first-win ZBS receipt without exposing it to spectators (`signalr.ts:790-825`). ## 13. Localization

The global RU/ENG control is visible even during login, defaults to English when `kotgh_locale` has not been saved, and persists every choice under that key. After authentication it invokes `SetLanguage` so the account and Discord surface share the preference (`App.vue:157-162`; wrapper `signalr.ts:1326-1328`). `Web/VueClient/src/i18n.ts` imports both backend catalogs plus untouched `characters.json` and translates rendered text/accessible attributes only. New `|>PhraseV2<|` records decode their embedded rendering; this includes arbitrary AI-generated Witcher clues because both texts travel inside the payload rather than entering a client dictionary. Old `|>Phrase<|` records match passive title plus exact Russian body against all 801 shared variants (`i18n.ts:1-93,219-347`). The Chronicle translates its complete source before Discord markdown becomes HTML, keeping dynamic-name templates intact (`FightAnimation.vue:1024-1039`).
