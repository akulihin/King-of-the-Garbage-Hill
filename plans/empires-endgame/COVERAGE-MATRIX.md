# Empire's Endgame — scope and ownership matrix

This is the closure ledger for the completion program. It prevents content that is absent
from the current config from disappearing between phase prompts. Update it whenever a raw
source, config carrier, designer verdict, or phase boundary changes.

Status meanings:

- **Complete** — shipped before or during the current program; later phases only regress it.
- **Owned** — guaranteed substrate/change-set owner.
- **Conditional** — the owner reconciles it, but it stays deferred when semantics or a
  required substrate remain undefined.
- **Review** — present in raw intent but not executable in this tranche; the accepted outcome
  keeps it unavailable unless a separately scoped replacement design supplies an owner and
  complete contract.
- **Out** — explicitly outside the confirmed 2026-07-16 scope.

On 2026-07-21 the designer's instruction to implement the proposed ledger changes superseded
the earlier boundary-only interpretation. Every existing configured non-Clash carrier is now
executable, all 106 standard card faces are live, Chess is playable, and the bundled non-Clash
configuration has zero deferral fields and zero non-empty `deferredSubfeatures`. Missing
numbers and mechanics use deterministic configurable defaults recorded in
`docs/EMPIRES-ENDGAME-DESIGN-REVIEW.md` `ES-001`–`ES-011`.

The current repository uses config schema 19 and save schema 18. The machine manifest owns
1,354 config carriers (`1,160` live / `120` blocked-semantic / `11` blocked-substrate / `63`
review) and 461 raw semantic identities (`67` live / `194` blocked-semantic / `52`
blocked-substrate / `133` review / `15` out). The configured blocked/review rows are the
separate disabled P14 Clash catalog, which the supersession does not route into the campaign.
Raw-only identities without a compatible carrier remain explicit provenance rather than
receiving fabricated systems. `ready-now` remains a transitional audit state and the current
manifest contains none. The maintained source spine freezes `1,149` JSON-export message
IDs across the 33-entry source inventory and requires residual review/out ownership for each
source. Stable raw semantic identities are a separate manually reviewed inventory; the
machine check detects drift in the maintained spine but does not infer new concepts from raw
prose. The extensionless prompt, population PNG and parent-message `Palach`/`Palach2`,
`EE_TD`, `EE_chest` and semantic text attachments are manually inspected and explicitly not
content-digested by the 1,149-ID spine. A maintained source/raw projection fingerprint pins
same-count message substitutions and exact raw→config links without claiming raw-file
discovery.
